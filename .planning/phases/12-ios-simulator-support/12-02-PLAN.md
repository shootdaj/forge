# Plan 12-02: iOS Build Verifier and UAT Platform Routing

<objective>
Create the Flutter iOS build verifier with `--no-codesign --simulator` flags, wire iOS Simulator into the UAT runner as an alternative to Android emulator, update the UAT module index with iOS simulator exports, and add integration/scenario tests for the full iOS UAT flow.
</objective>

<must_haves>
- Flutter iOS build verifier runs `flutter build ios --debug --no-codesign --simulator` and verifies .app bundle exists
- iOS build verifier self-skips on non-macOS platforms and when pubspec.yaml is absent
- UAT runner routes to iOS Simulator or Android emulator based on `config.testing.mobilePlatform`
- Same Maestro flow YAML files work against both Android and iOS (no platform-specific flows)
- All new iOS simulator functions exported from src/uat/index.ts
- Integration tests verify config-driven platform routing
- Scenario test covers full iOS UAT lifecycle with mocks
</must_haves>

```typescript

import * as path from "node:path";

import { skippedResult } from "./types.js";
import { execWithTimeout } from "./utils.js";
import { withFlutterLock } from "./flutter-lock.js";
```

Implement `flutterBuildIosVerifier: Verifier`:

1. Check `pubspec.yaml` exists in `config.cwd`. If not, return `skippedResult("flutter-build-ios", "No pubspec.yaml found")`.
2. Check `process.platform === "darwin"`. If not macOS, return `skippedResult("flutter-build-ios", "iOS builds only supported on macOS")`.
3. Build command: `flutter build ios --debug --no-codesign --simulator`
   - If `config.forgeConfig.testing.flutterBuildFlavor` is set, add `--flavor <flavor>`.
4. Run via `withFlutterLock(() => execWithTimeout(command, config.cwd, 600_000))` — 600s timeout (iOS builds are slower).
5. If exit code !== 0, return failed result with parsed build errors.
6. Verify `.app` bundle exists at `build/ios/iphonesimulator/Runner.app` (or `app-<flavor>-debug.app` with flavor).
7. If artifact not found, return failed result.
8. If all good, return passed result: "flutter build ios --debug --no-codesign --simulator succeeded, .app bundle verified".

Include `parseBuildErrors(output: string): string[]` helper — extract lines with "ERROR", "FAILURE", "error:" (same as flutter-build.ts).
</action>

### Task 3: Wire iOS Simulator into UAT Runner

<read_first>
- src/uat/runner.ts (runFlutterUAT function — main integration target)
- src/uat/ios-simulator.ts (iOS Simulator lifecycle from Plan 12-01)
- src/uat/ios-simulator-types.ts (types from Plan 12-01)
- src/uat/emulator.ts (withEmulator pattern)
- src/config/schema.ts (mobilePlatform config field from Plan 12-01)
</read_first>

<action>
Modify `src/uat/runner.ts`:

1. Add import at top:
```typescript
import { withSimulator } from "./ios-simulator.js";
import type { SimulatorBootOptions } from "./ios-simulator-types.js";
```

2. In `runFlutterUAT()`, after reading `avdName` and `flowsDir` from config, add platform routing:

```typescript
const mobilePlatform = config.testing.mobilePlatform || "android";
```

3. Replace the current `withEmulator()` call with platform-conditional logic:

For `"android"` (existing path):
```typescript
if (mobilePlatform === "android") {
  const emulatorOptions: EmulatorStartOptions = { avdName };
  uatResult = await withEmulator(emulatorOptions, async (emulatorHandle) => {
    return await withFlutterRun({ serial: emulatorHandle.serial }, async () => {
      // ... existing Maestro UAT logic (unchanged)
    });
  });
}
```

For `"ios"` (new path):
```typescript
if (mobilePlatform === "ios") {
  const simulatorOptions: SimulatorBootOptions = {
    deviceName: config.testing.iosSimulatorDevice || undefined,
  };
  uatResult = await withSimulator(simulatorOptions, async (simulatorHandle) => {
    return await withFlutterRun({ serial: simulatorHandle.udid }, async () => {
      // ... same Maestro UAT logic (identical to Android path)
    });
  });
}
```

The key insight: the inner Maestro UAT logic (flow generation, test execution, gap closure) is IDENTICAL for both platforms. Only the outer lifecycle wrapper changes (`withEmulator` vs `withSimulator`), and the device identifier passed to `withFlutterRun` and `executeMaestroUAT` changes (Android serial vs iOS UDID).

Extract the inner Maestro UAT logic into a helper function to avoid duplication:
```typescript
async function runMaestroUATInner(
  deviceId: string,
  workflows: UATWorkflow[],
  safetyPrompt: string,
  flowsDir: string,
  maxRetries: number,
  ctx: UATContext,
): Promise<UATResult> { ... }
```

Then both paths call `runMaestroUATInner(emulatorHandle.serial, ...)` or `runMaestroUATInner(simulatorHandle.udid, ...)`.
</action>
