# Plan 16-02: Parallel Gap Fixing in Incremental Compliance Loop

<objective>
Modify `runIncrementalComplianceLoop()` to fix independent gaps concurrently using the graph utilities from Plan 01. Within each color group (independent gaps), fixes run in parallel with configurable concurrency. Within each cluster of overlapping gaps, the Phase 13 sequential fix-one-verify-one pattern is preserved. After all parallel fixes in a wave complete, a full regression check runs.
</objective>

<must_haves>
- Independent gaps (different files) are fixed concurrently
- Overlapping gaps (shared files) are fixed sequentially
- Phase 13's fix-verify-commit/revert pattern preserved within each gap fix
- Post-wave regression check after parallel fixes complete
- Gap count monotonically decreases (convergence preserved)
- Configurable max concurrency from ForgeConfig.maxParallelGapFixes
</must_haves>

3. Replace the sequential `for (const gap of gaps)` loop with parallel execution:
```typescript
// Analyze file overlap to find independent groups
const independentGroups = analyzeGapOverlap(gapsWithFiles);
const maxConcurrency = ctx.config.maxParallelGapFixes ?? 3;

// Process each group of independent gaps
for (const group of independentGroups) {
  // Create fix tasks for each gap in this independent group
  const fixTasks = group.map((gapId) => {
    const gap = gapsWithFiles.find((g) => g.id === gapId)!;
    return () => fixSingleGap(gap, round, currentPassing, ctx, requirementsDoc);
  });

  // Run independent gaps concurrently (up to maxConcurrency)
  const results = await limitConcurrency(fixTasks, maxConcurrency);

  // Process results: update passing set and deferred gaps
  for (let i = 0; i < results.length; i++) {
    const result = results[i];
    const gapId = group[i];
    if (result.status === "fulfilled") {
      if (result.value.fixed) {
        currentPassing.push(gapId);
      } else {
        const gap = gapsWithFiles.find((g) => g.id === gapId)!;
        deferredGaps.push({ id: gap.id, description: gap.description });
      }
    } else {
      // Promise rejected — treat as deferred
      const gap = gapsWithFiles.find((g) => g.id === gapId)!;
      deferredGaps.push({ id: gap.id, description: gap.description });
    }
  }

  // Post-group regression check on all previously-passing requirements
  if (currentPassing.length > 0) {
    const regressionVerdicts = await verifyRequirementsBatch(
      currentPassing, ctx, requirementsDoc
    );
    const regressions = regressionVerdicts.filter((v) => !v.passed);
    if (regressions.length > 0) {
      console.log(
        `[compliance] Post-group regression detected: ${regressions.length} requirement(s) regressed — ` +
        regressions.map((r) => r.id).join(", ")
      );
      // Note: individual gap fixes already handle their own commit/revert
      // Post-group regressions indicate a cross-gap interaction that file analysis missed
      // These regressions are logged but the affected requirements will be caught in next round
    }
  }
}
```

4. Extract the single-gap fix logic into a helper function `fixSingleGap`:
```typescript
async function fixSingleGap(
  gap: GapWithFiles,
  round: number,
  currentPassing: string[],
  ctx: PipelineContext,
  requirementsDoc: string,
): Promise<{ fixed: boolean }> {
  // Record restore point
  let restorePoint = "";
  try {
    restorePoint = execGitCommand("git rev-parse HEAD", ctx);
  } catch { /* git not available */ }

  // Fix the gap
  const fixResult = await runStep(
    `fix-gap-incremental-${gap.id}-round-${round}`,
    {
      prompt: buildIncrementalGapFixPrompt(
        gap.id, gap.description, round, currentPassing, requirementsDoc
      ),
      verify: async () => true,
    },
    ctx.stepRunnerContext,
    ctx.costController,
  );

  // Handle watchdog timeout
  if (fixResult.status === "timed_out") {
    console.log(`[compliance] Gap fix for ${gap.id} timed out — deferring`);
    if (restorePoint) {
      try { execGitCommand(`git reset --hard ${restorePoint}`, ctx); }
      catch { console.warn(`[compliance] Warning: git reset failed for ${gap.id}`); }
    }
    return { fixed: false };
  }

  // Commit the fix
  if (restorePoint) {
    try {
      execGitCommand(`git add -A && git commit -m "fix: spec compliance - ${gap.id}"`, ctx);
    } catch { /* nothing to commit */ }
  }

  // Verify the fixed requirement
  const fixVerdict = await verifyRequirement(gap.id, ctx, requirementsDoc);
  if (!fixVerdict.passed) {
    console.log(`[compliance] Fix for ${gap.id} did not resolve the gap — reverting`);
    if (restorePoint) {
      try { execGitCommand(`git reset --hard ${restorePoint}`, ctx); }
      catch { console.warn(`[compliance] Warning: git reset failed for ${gap.id}`); }
    }
    return { fixed: false };
  }

  console.log(`[compliance] Fix for ${gap.id} verified`);
  return { fixed: true };
}
```

**Key differences from Phase 13 sequential loop:**
- The per-gap regression check (checking ALL passing reqs after each fix) is removed from individual gap fixes for concurrent gaps — it would be invalid since multiple fixes run simultaneously
- Instead, a post-group regression check runs after each group of concurrent fixes completes
- Sequential behavior is preserved for overlapping gaps (they end up in the same group via graph coloring, so only 1 runs at a time within that group... actually no, same color means independent. Overlapping gaps get DIFFERENT colors, so they run in different groups sequentially. The key insight: graph coloring ensures gaps in the same group don't share files, so concurrent execution within a group is safe)
- The `currentPassing` array is shared across the entire round and updated after each group completes
