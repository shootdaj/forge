# Plan 13-01: Incremental Compliance Engine + Regression-Aware Prompts

<objective>
Replace the batched spec compliance fix loop with an incremental fix-one-verify-one engine. Each gap gets its own SDK session, is individually verified (including regression checks on all previously-passing requirements), and is committed or reverted via git. Add regression-aware prompt builders.
</objective>

<action>
Add a new exported function `runIncrementalComplianceLoop` to `src/pipeline/spec-compliance.ts`:

```typescript
export async function runIncrementalComplianceLoop(
  requirementIds: string[],
  ctx: PipelineContext,
): Promise<SpecComplianceResult>
```

Implementation flow for each round:
1. Run `verifyRequirementsBatch()` to get initial verdicts (passing set vs gap set)
2. Record the gap count for this round in gapHistory
3. If no gaps, return converged
4. For each gap (one at a time):
   a. Record git restore point: `const restorePoint = execGitCommand('git rev-parse HEAD', ctx)`
   b. Run `runStep()` with `buildIncrementalGapFixPrompt()` — pass the current passing set
   c. Commit the fix: `execGitCommand('git add -A && git commit -m "fix: spec compliance - {requirementId}"', ctx)`
   d. Re-verify the fixed requirement using `verifyRequirement()`
   e. Run regression check: `verifyRequirementsBatch(passingRequirements, ctx, requirementsDoc)` — check all previously-passing requirements still pass
   f. If fix verified AND no regressions: update passing set (add this ID), continue to next gap
   g. If regression detected: revert via `execGitCommand('git reset --hard {restorePoint}', ctx)`, add gap to deferred list, log the regression
5. After all gaps attempted: check monotonicity (new gap count <= previous round gap count)
6. If gaps remain and converging: start next round
7. If not converging or max rounds hit: return result

Add a helper function:
```typescript
function execGitCommand(cmd: string, ctx: PipelineContext): string
```
This uses `ctx.execFn` if available (for testing), otherwise uses `child_process.execSync`.

The function must handle the case where `ctx.execFn` is undefined (production) by importing and using `execSync` from `node:child_process`.
</action>
