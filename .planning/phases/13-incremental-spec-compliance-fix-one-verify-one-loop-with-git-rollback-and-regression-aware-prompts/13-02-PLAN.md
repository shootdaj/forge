2. `TestIncrementalCompliance_FixCausesRegression_Reverts` — Mock: 2 gaps (REQ-01 fails, REQ-02 passes). Fix REQ-01 causes REQ-02 to now fail. Assert: git reset --hard was called with restore point, REQ-01 is deferred, result shows REQ-01 in remainingGaps.

3. `TestIncrementalCompliance_MultipleGaps_MixedResults` — Mock: 3 gaps (REQ-01, REQ-02, REQ-03 fail). Fix REQ-01 succeeds. Fix REQ-02 causes regression, is reverted. Fix REQ-03 succeeds. Assert: gap history shows decrease from 3 to 1 (REQ-02 remains), 2 commits and 1 revert.

4. `TestIncrementalCompliance_MonotonicGapDecrease` — Mock: Round 1 fixes 2 of 3 gaps. Round 2 fixes remaining 1. Assert: gapHistory is [3, 1, 0], converged is true.

5. `TestIncrementalCompliance_NotConverging_StopsLoop` — Mock: Same gaps persist across rounds (all fixes cause regressions). Assert: loop stops, converged is false.

For each test, create a mock context where:
- `executeQueryFn` returns appropriate batch verify results (controlling which requirements pass/fail)
- `execFn` tracks git commands called (record in array) and returns realistic values
- State manager tracks updates

Use the existing `makeMockContext` pattern but extend it to support:
- Dynamic verify results (pass/fail changes based on whether a fix was applied and whether regression occurred)
- An `execFn` that records commands and returns mock git output
