# Plan 11-01: Flutter Run Daemon and Maestro Test Execution

<objective>
Create the two core modules for Phase 11: flutter run daemon management (`flutter-run.ts`) and Maestro test execution with JUnit parsing (`maestro.ts`). These are self-contained modules with injectable dependencies, matching the pattern established by `emulator.ts` in Phase 10. The flutter run module handles spawning `flutter run` as a daemon, detecting the ready signal, and guaranteed PID-based teardown. The Maestro module runs `maestro test --format junit`, parses JUnit XML via `junit2json`, and implements defense-in-depth result reconciliation.
</objective>

<action>
Create `src/uat/flutter-run.ts` with the following functions:

**1. `startFlutterRun(options: FlutterRunOptions): FlutterRunHandle`**
- Spawn: `spawn('flutter', ['run', '-d', options.serial], { detached: true, stdio: 'pipe', cwd: options.projectDir })` using `options.spawnFn ?? defaultSpawnFn`
- Capture PID immediately: `const pid = child.pid ?? 0`
- Track early exit via `child.on('error')` and `child.on('exit')` listeners
- Try to `child.unref()` (catch for test mocks)
- Return `{ pid, startedAt: new Date().toISOString(), process: child }`

**2. `waitForFlutterRunReady(handle: FlutterRunHandle, options?: FlutterRunWaitOptions): Promise<void>`**
- Default timeout: 120_000ms (2 minutes)
- Listen on `handle.process.stdout` for data events
- Accumulate stdout chunks, scan for "Flutter run key commands" substring (case-insensitive match on "flutter run key commands")
- When found, resolve the promise
- If timeout reached before signal, throw `FlutterRunReadyTimeoutError(timeoutMs)`
- If process exits before signal, throw `FlutterRunStartError(exitCode)`
- Use `Promise.race([readyPromise, timeoutPromise])` pattern

**3. `stopFlutterRun(handle: FlutterRunHandle): Promise<void>`**
- Never throws — teardown errors are logged as warnings
- Layer 1: `process.kill(handle.pid, 'SIGTERM')` wrapped in try/catch
- Wait up to 5 seconds for process to exit (poll with `process.kill(pid, 0)` every 500ms)
- Layer 2: `process.kill(handle.pid, 'SIGKILL')` if still alive, wrapped in try/catch

**4. `registerFlutterRunCleanup(handle: FlutterRunHandle): () => void`**
- Register `process.on('exit')`, `process.on('SIGINT')`, `process.on('SIGTERM')` handlers that call `process.kill(handle.pid, 'SIGKILL')`
- Return deregister function that removes all three listeners

**5. `withFlutterRun<T>(options: FlutterRunOptions, callback: (handle: FlutterRunHandle) => Promise<T>): Promise<T>`**
- Call `startFlutterRun(options)` to get handle
- Call `registerFlutterRunCleanup(handle)` to get deregister
- In try block: `await waitForFlutterRunReady(handle, { timeoutMs: options.readyTimeoutMs })` then `return await callback(handle)`
- In finally block: `deregister()` then `await stopFlutterRun(handle)`

All functions use `const defaultSpawnFn = (command, args, options) => spawn(command, args, options)` from `node:child_process`.

Export all 5 functions.
</action>

**Step 2:** Create `src/uat/maestro.ts` with:

**1. `runMaestroTest(options: MaestroTestOptions): Promise<{ exitCode: number; reportPath: string }>`**
- Construct command: `maestro test --format junit --output ${outputPath} ${options.flowsDir}`
  - Default outputPath: `.forge/maestro-report.xml`
  - If `options.serial` provided, prepend `--device ${options.serial}`
- Execute via `options.execFn ?? defaultExecFn` wrapped in try/catch
- On success: `{ exitCode: 0, reportPath: outputPath }`
- On error: extract exit code from error, return `{ exitCode, reportPath: outputPath }`

**2. `parseMaestroJUnit(xmlContent: string): MaestroResult`**
- Import `parse` from `junit2json`
- Parse XML: `const result = await parse(xmlContent)` (junit2json returns a JUnit object)
- Map `testsuite.testcase` array to `MaestroFlowResult[]`:
  - `name`: testcase.name or testcase.classname
  - `passed`: no `failure` or `error` child elements
  - `durationMs`: `parseFloat(testcase.time || "0") * 1000`
  - `error`: `testcase.failure?.[0]?.message || testcase.error?.[0]?.message || undefined`
- Calculate totals: `totalFlows`, `passedFlows`, `failedFlows`
- `passed`: `failedFlows === 0`
- Return `MaestroResult`

Note: `junit2json` may export its parse function as default or named. Check the actual API when importing. The package parses JUnit XML into a JS object with `testsuite` containing `testcase` arrays.

**3. `reconcileResult(exitCode: number, junitResult: MaestroResult): MaestroResult`**
Defense-in-depth reconciliation:
- If exitCode === 0 AND junitResult.passed → return junitResult (PASS)
- If exitCode === 0 AND !junitResult.passed → return junitResult (FAIL — trust XML over exit code)
- If exitCode !== 0 AND junitResult.passed → return junitResult with `passed: true` (PASS — known Maestro regression, trust XML)
- If exitCode !== 0 AND !junitResult.passed → return junitResult (FAIL)

**4. `executeMaestroUAT(options: MaestroTestOptions, fs?: { readFileSync: (p: string, enc: string) => string; existsSync: (p: string) => boolean }): Promise<MaestroResult>`**
High-level function:
1. Call `runMaestroTest(options)` to get exitCode and reportPath
2. Read report XML from `reportPath` via `fs.readFileSync`
3. If XML file doesn't exist: return `{ passed: false, totalFlows: 0, passedFlows: 0, failedFlows: 1, flowResults: [{ name: "maestro-test", passed: false, durationMs: 0, error: "JUnit report not generated" }] }`
4. Call `parseMaestroJUnit(xmlContent)`
5. Call `reconcileResult(exitCode, junitResult)`
6. Return reconciled result

**5. `maestroResultToWorkflowResults(result: MaestroResult): WorkflowResult[]`**
Maps MaestroResult to existing WorkflowResult[] for gap closure compatibility:
- For each flowResult in result.flowResults:
  - `workflowId`: `maestro-${flowResult.name}`
  - `passed`: flowResult.passed
  - `stepsPassed`: flowResult.passed ? 1 : 0
  - `stepsFailed`: flowResult.passed ? 0 : 1
  - `errors`: flowResult.error ? [flowResult.error] : []
  - `durationMs`: flowResult.durationMs

Export all 5 functions.
</action>
