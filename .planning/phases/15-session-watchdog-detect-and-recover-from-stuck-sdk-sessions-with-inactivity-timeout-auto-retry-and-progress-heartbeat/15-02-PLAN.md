# Plan 15-02: Session Watchdog Implementation

<objective>
Implement the core watchdog module that wraps executeQuery calls with inactivity timeout detection, heartbeat emission, session abort, and retry logic. Integrate it into the step runner.
</objective>

<must_haves>
- Watchdog detects inactivity based on SDK message stream activity, not wall clock
- After configurable timeout (default 120s) of no message activity, session is killed via AbortController
- Periodic heartbeat lines emitted to stdout during inactivity: "[forge] Ns since last activity... (step: STEP_NAME)"
- Max retries per step configurable (default 2); after exhausting, step marked failed
- forge-state.json updated with last_heartbeat timestamp
- Existing step runner behavior unchanged when watchdog is not triggered
</must_haves>

Create `src/step-runner/watchdog.ts` with the following exports:

1. **`WatchdogConfig` interface:**
```typescript
export interface WatchdogConfig {
  inactivityTimeoutMs: number;    // converted from seconds at call site
  heartbeatIntervalMs: number;    // converted from seconds at call site
  maxRetries: number;
  stepName: string;
}
```

2. **`WatchdogResult<T>` type:**
```typescript
export type WatchdogResult<T> =
  | { status: "completed"; result: T }
  | { status: "timeout"; attempt: number; elapsedMs: number };
```

3. **`executeWithWatchdog<T>` function:**
```typescript
export async function executeWithWatchdog<T>(
  executeFn: (abortController: AbortController) => Promise<T>,
  config: WatchdogConfig,
  callbacks: {
    onHeartbeat: (secondsSinceLastActivity: number, stepName: string) => void;
    onTimeout: (attempt: number, stepName: string) => void;
    onRetry: (attempt: number, stepName: string) => void;
  },
): Promise<WatchdogResult<T>>
```

Implementation logic:
- Create AbortController for each attempt
- Start a heartbeat timer that fires every `heartbeatIntervalMs` milliseconds
- The heartbeat timer tracks time since last activity
- Use `setTimeout` to create the inactivity timeout
- Race the executeFn against the timeout
- On timeout: call `abortController.abort()`, call `callbacks.onTimeout`, return `{ status: "timeout" }`
- On success: clear all timers, return `{ status: "completed", result }`
- On each heartbeat tick: call `callbacks.onHeartbeat(elapsedSeconds, stepName)`

Key: the inactivity timeout must be RESET whenever the executeQuery callback shows message activity. Since executeQuery processes the stream internally and returns a Promise, the watchdog wraps the entire call. The existing 5-minute timeout in query-wrapper.ts (line 265) handles per-message inactivity within the stream. The watchdog handles the entire session level — if executeQuery itself hangs (e.g., SDK never emits any messages, or blocks on startup).

4. **`runWithRetries<T>` function:**
```typescript
export async function runWithRetries<T>(
  executeFn: (abortController: AbortController) => Promise<T>,
  config: WatchdogConfig,
  callbacks: {
    onHeartbeat: (secondsSinceLastActivity: number, stepName: string) => void;
    onTimeout: (attempt: number, stepName: string) => void;
    onRetry: (attempt: number, stepName: string) => void;
  },
): Promise<{ result: T; attempts: number } | { timedOut: true; attempts: number }>
```

Implementation: loop up to `config.maxRetries + 1` attempts (1 initial + N retries). Each attempt calls `executeWithWatchdog`. If timeout, call `callbacks.onRetry` and continue. If completed, return result. After all attempts exhausted, return `{ timedOut: true }`.
</action>

2. After the budget check (line 75) and before calling executeQueryFn (line 79), set up the watchdog:

```typescript
// ─── 2. Execute query with watchdog ───
const watchdogConfig = {
  inactivityTimeoutMs: (config.watchdog?.inactivityTimeoutSeconds ?? 120) * 1000,
  heartbeatIntervalMs: (config.watchdog?.heartbeatIntervalSeconds ?? 30) * 1000,
  maxRetries: config.watchdog?.maxRetries ?? 2,
  stepName: name,
};

const watchdogResult = await runWithRetries(
  async (abortController) => {
    return executeQueryFn({
      prompt: opts.prompt,
      maxBudgetUsd: opts.maxBudgetUsd ?? config.maxBudgetPerStep,
      maxTurns: opts.maxTurns ?? config.maxTurnsPerStep,
      model: opts.model ?? config.model,
      cwd: opts.cwd,
      outputSchema: opts.outputSchema,
      abortController,
    });
  },
  watchdogConfig,
  {
    onHeartbeat: (seconds, stepName) => {
      console.log(`[forge] ${seconds}s since last activity... (step: ${stepName})`);
      // Update state with heartbeat timestamp
      stateManager.update((state) => ({
        ...state,
        lastHeartbeat: new Date().toISOString(),
      })).catch(() => { /* heartbeat state update is best-effort */ });
    },
    onTimeout: (attempt, stepName) => {
      console.log(`[forge] Session timed out after ${watchdogConfig.inactivityTimeoutMs / 1000}s inactivity (step: ${stepName}, attempt: ${attempt})`);
    },
    onRetry: (attempt, stepName) => {
      console.log(`[forge] Retrying step ${stepName} (attempt ${attempt + 1}/${watchdogConfig.maxRetries + 1})`);
    },
  },
);

// Handle watchdog exhaustion (all retries timed out)
if ('timedOut' in watchdogResult) {
  return {
    status: "timed_out",
    costUsd: 0,
    attempts: watchdogResult.attempts,
    timeoutSeconds: watchdogConfig.inactivityTimeoutMs / 1000,
    error: `Step ${name} timed out after ${watchdogResult.attempts} attempt(s) — no SDK activity for ${watchdogConfig.inactivityTimeoutMs / 1000}s per attempt`,
  } satisfies StepResultTimedOut;
}

const queryResult = watchdogResult.result;
```

The rest of the function continues as before with `queryResult`.
